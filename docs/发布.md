# APK 发布

每个版本都需要用户在本机审核页确认。代理不能代点确认，也不能绕过页面发布；规则见 [AGENTS.md](../AGENTS.md#github-release-发布)。公开仓库为 `GStarP/oh-my-life-record`，不上传个人数据、凭证或签名私钥。

## 版本与构建

Android 原生壳方案从 `v1.0.0` 开始。`package.json` 的版本必须等于 Android `versionName`；`versionCode` 是安装升级序号，独立递增。例如公开版本为 `1.0.0`、安装序号为 `3`，可覆盖安装同签名且安装序号较小的包。

本项目个人使用现有签名的 debug APK，界面使用 Vite 生产构建。GitHub Release 是下载发布页，与 Android debug / release 构建类型无关。

```sh
pnpm android:package
```

工具先记录源码摘要，再构建并核对源码未变化；检查应用名、包名、版本和固定签名。输出位于 Git 忽略的 `artifacts/`：

- `OhMyLife-v1.0.0.apk`：带版本号的安装包。
- `OhMyLife-v1.0.0.apk.sha256`：校验文件。
- `release.json`：版本、签名、APK 摘要与源码指纹。
- `release-notes.md`：待发布说明，可在打开审核页前编辑。

后续版本使用对应版本号命名，不保留无版本号附件别名。代码变化后须重新验证、打包和审核。

## 审核与发布

源码使用仓库的 SSH 地址推送，需要已有 GitHub SSH 推送权限。发布附件使用 GitHub CLI，需安装并由用户完成一次登录：

```sh
gh auth login --web
pnpm release:review
```

`pnpm release` 会先打包，再打开同一个审核页，也不会直接发布。审核服务器仅绑定本机随机端口，使用随机令牌校验请求，审核页采用桌面两栏布局：主卡片只展示版本、仓库、目标分支、安装包、大小、发布说明及必要的标签确认；右侧分别展示 GitHub CLI 登录状态、发布进度与结果。摘要和源码校验在后台完成。

- **取消**：关闭工具，不改变 Git 索引、提交、标签或远端，等待下一步指示。
- **确认发布**：复核登录身份、源码、APK、说明和远端状态；固定源码提交；将 main 和标签原子推送；建立草稿、上传版本化 APK 和摘要；下载核对后发布为 latest。

当前仓库存在尚无 Release 的 `v1.0.0` 标签。首次发布会在页面明确展示其调整，并要求单独勾选；只有确认后才把标签指向已审核的 Android 源码。已发布版本不能调整标签或替换附件，必须提升版本号。

例如审核 `v1.0.0` 后又修改代码或说明，确认会拒绝执行，需要重新打包或重新打开页面。main 只允许快进；同名标签使用审核时的对象 ID 作为精确租约，防止覆盖其他人的变更。

发布出错会停止，不自动批准重试。草稿通过 `gh release view` 查询，按标签的 REST 接口仅用于检查已发布版本。已经上传的草稿保留；再次审核相同源码、说明和产物时，可复用摘要一致的草稿附件。不同内容不能覆盖。若 GitHub CLI 未登录，页面仍可查看，但确认按钮不可用；登录后点击“重新检查”。

## 下载地址

- 固定入口：[最新发布页](https://github.com/GStarP/oh-my-life-record/releases/latest)。
- 指定版本 APK：`https://github.com/GStarP/oh-my-life-record/releases/download/v1.0.0/OhMyLife-v1.0.0.apk`。

首个正式 Release 发布前下载链接不可用。由于文件名含版本号，固定入口使用 latest 发布页。链接规则见 [GitHub 官方说明](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。
