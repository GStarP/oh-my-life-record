# 个人生活记录 App — 设计文档

> 本文档描述当前产品范围和运行架构。术语定义见 `CONTEXT.md`，不可逆或有取舍的决策见 `docs/adr/`；S3/R2 对象格式单独见 `docs/cloud-storage-format.md`。

## 1. 定位与总原则

单用户个人生活记录应用，移动优先 PWA。无用户体系，默认不同设备不同时编辑。

- **IndexedDB 是业务数据唯一事实来源**；S3（Cloudflare R2）保存云端快照与图片。
- **月只是存储结构，不是查询结构**：IndexedDB 记录是时间倒序的连续序列，查询层无"月"概念；"月"只用于 S3 分片与同步状态。
- **云端优先**：本地修改永远不会覆盖云端已存在的版本；任何覆盖本地（丢失修改）的操作必须经用户确认。
- **一切设计尽可能简单、可靠**：无自动上传、无 debounce、无定时同步、无 operation log、无 CRDT、无记录级合并、无隐式云端删除。

## 2. 技术栈

- Vite + React + TypeScript，托管于 Cloudflare Workers Static Assets（与 R2 同账号）；未命中实体文件的路径统一回退到 `index.html`，由前端路由接管。
- 路由：`tanstack-router`；状态管理：`jotai`（轻量原子状态）；虚拟列表：`@tanstack/react-virtual`；UI：Chakra v3 + 项目内 `docs/references/oh-my-mobile-design-system/`（语义 token、明暗自适应、只使用组件）；ID：`ulidx`（ULID）；时间：date-fns + date-fns-tz + @date-fns/utc（固定 UTC+8，ADR-0003/0006）。
- 云端凭证：用户配置 R2 端点 + Access Key/Secret，存于 localStorage（见 ADR-0001）；前端本地 SigV4 签名，无签名服务。首次启动无凭证或运行中云端异常 → 全屏凭证配置弹窗（凭证无效或网络不可达时禁止绕过），验证成功后保存；正常情况下由设置页入口打开。应用不提供离线工作流，云端异常时阻断使用。
- 本地存储：IndexedDB（记录 + 暂存图片 + 同步状态），见 ADR-0005。
- PWA：`public/manifest.webmanifest` 提供 standalone 启动配置，`public/sw.js` 提供静态资源缓存；应用图标和生产构建一起交付。

### 代码组织

代码首先按业务能力归属，不再按 `domain / ports / infrastructure` 技术角色分层：

- `app/`：只放应用壳、路由入口和跨业务能力的生命周期组装。
- `features/records/`：记录模型与写操作；列表、编辑、图片分别位于 `list/`、`editor/`、`images/`。
- `features/type-templates/`：类型模板模型、规则、状态和界面；固定图标能力位于 `icons/`。
- `features/cloud/`：云端清理与状态；凭证、R2 读写、同步分别位于 `credential/`、`r2/`、`sync/`。
- `features/storage/`：本地存储接口与 IndexedDB 实现。
- `features/preferences/`、`features/notifications/`：偏好与通知能力。
- `utils/`：与任何业务能力都无关的通用代码，目前只放固定 UTC+8 的时间换算。

类型、业务规则、外部读写和界面都放在拥有它们的业务目录内；需要测试替身的接口也与真实实现就近放置。新增代码先回答“它属于哪个业务能力”，只有确实没有业务语义时才进入 `utils/`。持久化格式保持 v1，仅接受当前规范（见 ADR-0005）。

## 3. 数据模型

```ts
type LifeRecord = {
  id: string              // 不可变 ULID
  time: Date              // 绝对瞬间；归属与展示按 UTC+8（见 ADR-0006）
  type: string            // 记录类型文本，也可以为空；表单可按同名类型模板显示预置属性
  name: string            // 简短名称；未填写 = 空字符串（字段必填，表单可留空）
  description: string     // 无描述 = 空字符串（必填）
  images: string[]        // 图片 ID 引用；无图 = 空数组（必填）
  attributes: { [k: string]: string | number | boolean } // 无属性 = 空对象（必填）
}
```

- TS 类型名为 `LifeRecord`（避免遮蔽内置工具类型 `Record<K,V>`），领域术语仍为「记录」。
- `name` / `description` / `images` / `attributes` 不区分「不存在」与「空值」：无名称或描述即空串、无图即空数组、无属性即空对象。云端记录必须包含这些字段，不补齐旧格式。
- 同类型记录属性可以不一致；统计（若未来做）按类型分组后本地全量计算。
- 图片 ID 不可变；同一图片可被多条记录共享，S3 只存一份。

### 本地存储（IndexedDB，见 ADR-0005）

- `records`：全部记录，索引 `id` / `time` / `type`。列表按 `time` 倒序游标分页，实现懒加载。
- `images`：仅存放**待上传**图片（id → Blob + createdAt），上传成功后删除本体；存在即未上传。
- `partitionState`：`{ month, remoteRevision, dirty }`，仅服务同步，不服务查询。
- `typeTemplates`：类型 → 当前类型模板；`typeTemplateState` 保存全局模板集合的 `remoteRevision` / `dirty`。

## 4. 云端结构

云端对象键名、JSON 字段、图片格式和对象关联关系只维护在
[`docs/cloud-storage-format.md`](cloud-storage-format.md)。本文不重复定义桶内数据格式；同步如何使用这些对象见下一节。

当前格式的 `schemaVersion` 为 `1`，记录按 UTC+8 月份分片，类型模板集合单独维护全局版本。具体字段和示例以存储格式文档为准。

## 5. 同步模型

系统只有两种行为：**同步按钮**（上传与下载的统一入口，用户主动触发）、**启动/回前台只读检查**（只对比版本，不拉数据）。

### 5.1 本地修改

所有用户操作首先且只修改 IndexedDB：新增/修改/删除记录 → 计算所属 UTC+8 月份（跨月改 `time` 标两个月）→ 对应月 `dirty = true`。不访问 S3。

### 5.2 同步按钮（上传 + 下载的统一入口）

同步按钮是**唯一的数据写入入口**（下载与上传都在其中），用户主动点击触发：

```
① 重读 manifest（防启动后云端又变化）
② 逐月比较记录分片，并比较一次全局类型模板版本，分三路：
   云端 > 本地         → 可下载（GET → 解析校验 → 分片替换本地）
   云端 = 本地 且 dirty → 可上传（传新图 → 写月 JSON 自校验 → PUT）
   云端 = 本地 且无修改  → 无操作
③ 下载与上传按「月」粒度同时进行：a 月上传、b 月下载是正常同步，互不干扰；
   只有同一个月「云端更高 且 本地 dirty」才是冲突。
④ 存在冲突（云端 > 本地 且 本地 dirty）→ 全局一票否决（见 §5.4）：
   弹确认（列出冲突月份和类型模板）
   确认 → 冲突月/模板集合以云端覆盖本地
   取消 → 本次同步整体中止，无任何数据变化
⑤ 需要上传时：传新图片（仅"被本地记录引用且云端尚无"的图，见 §6.3）
   → 写各 dirty 月 JSON → PUT records/YYYY-MM.json
   → 若模板 dirty，PUT type-templates.json
   → PUT manifest.json（提交点；若此步失败，下次重读旧 manifest 幂等重写自愈）
   → 本地置 dirty=false、更新 remoteRevision
⑥ Toast：本次有上传 →「已更新云端」；本次有下载 →「已更新本地」；
   同时上传与下载 →「已同步云端和本地」；无任何变更 →「已是最新」
```

不可恢复的连接或写入错误会中止本次同步；损坏的单个云端文件只报告对应的 broken 状态，不覆盖本地。已传图片有标记，重试幂等。冲突未决时用户可继续本地编辑。

### 5.3 启动/回前台检查（只读，不拉取数据）

GET manifest → 逐分片比较 `remoteRevision`：

- 云端更新 → 标记该月「有云端更新」，同步按钮显示对应图标和文案；**不下载任何数据**。
- 版本一致 → 无操作。

检查不改变任何本地状态；数据拉取只发生在用户点同步按钮时（§5.2）。云端数据损坏在同步按钮下载校验时发现并弹窗提示。

**分片替换（下载方向的实现）**：与上传对称的月度全量替换，不增量、不合并。

```
tx = idb.transaction(['records', 'partitionState'], 'readwrite')
records.index('time').delete(UTC+8月范围)   // ① 删本地当月全部
for rec of json.records: records.put(rec)   // ② 写入云端当月全部
partitionState.put({ month, remoteRevision: cloudRev, dirty: false })  // ③
```

① ② ③ 同一事务，原子生效或整体回滚；失败则本地保持原状，下次同步重试。月份归属按记录 `time` 的 Date 值换算为 UTC+8，不依赖设备时区。

### 5.4 冲突

- 记录按月判定，类型模板按全局集合判定，整体 winner-take-all，无记录级合并。
- **全局一票否决**：任一冲突存在时，点击同步必弹确认，不可绕过。
- 确认弹窗：列出冲突月份和类型模板（无需更细信息）→ 确认则冲突对象全部以云端覆盖本地；取消则本次同步整体中止。
- 挂起不打断日常使用：不弹窗打扰，仅同步按钮指示器持续提示；用户可继续本地编辑。

### 5.5 同步按钮状态

同步按钮使用 subtle 样式，用图标和文案直接表达状态，不使用角标，也不依赖颜色区分：

| 状态 | 图标语义 | 文案 |
|---|---|---|
| 云端有更新（可下载） | 云端下载 | 有更新 |
| 本地有未上传修改（可上传） | 云端上传 | 待上传 |
| 同时存在上传与下载需求 | 双向同步 | 需同步 |
| 均无 | 刷新/同步 | 已同步 |

同月的上传+下载并存是冲突，在同步时判断，不作为独立按钮状态。按钮显示「已同步」时，点击只重新执行一次只读检查；如果检查发现变化，只更新按钮状态，不在同一次点击中继续同步。

已完成云端配置且云端可达时按钮可用；未完成配置、云端异常、离线或同步进行中时禁用或由全局凭证弹窗阻断。应用不提供离线工作流。

## 6. 图片（见 ADR-0004）

图片仅来自相册选择，无拍摄概念。**S3 是图片唯一事实来源；本地永不积累已上传图片。**

### 6.1 选图

选图 → 本地压缩转 WebP（最长边 2048、q80；HEIC 解码失败时保留原始 Blob）→ 生成图片 ID → 本体暂存于 IndexedDB `images`（存在即待上传）→ 显示走本地。正常情况下不保留原图。

### 6.2 保存/显示

- 保存记录仅写图片 ID 引用，无网络。
- 显示：先探测本地暂存区 → 有则显示本地；无则通过 ImageManager 优先读取 Cache Storage，未命中时用本地 SigV4 签名生成短期 GET URL 从 S3 拉取并缓存；失败显示错误占位。已上传图片不进入业务数据，按需从云端拉取。

### 6.3 上传与删除

- 图片不自动上传；手动上传时只传「被本地记录引用且云端尚无」的图（预防云端孤儿），成功后从本地暂存区删除本体。
- **无任何隐式云端删除**：删除记录、移除图片、异常遗留产生的孤儿一律留存云端。
- 本地孤儿（无记录引用的暂存图）：关闭未提交的新建内容或删除记录时立即清理；启动时兜底清理「无引用且超 7 天」者。
- 云端孤儿：仅由用户手动触发「清理未引用图片」（扫描本地全部记录 + 云端全部图片，删除无引用者，确认后执行）。

### 6.4 图片模块边界

- `app/runtime.ts` 创建应用级唯一 `ImageManager`；它不依赖 React，统一处理本地暂存、Cache Storage、签名 URL、Object URL、并发去重和 32 MiB LRU。
- 记录卡片和编辑表单只通过 `useImageSources` 获取可显示 URL；当前显示位置持有 lease，离开后资源进入 LRU，不主动销毁 manager。
- `features/records/images/image-staging` 只负责压缩、暂存和本地孤儿清理，不创建或释放展示用 Object URL；图片 ID 是两个模块之间的唯一交接数据。

## 7. 列表与查询

- v1 不做统计。
- 筛选：仅按类型；输入完成后按完整类型匹配已加载记录，不建立类型注册表或候选下拉。
- 虚拟列表（时间倒序），**以月为加载单元**：
  - 分页单元 = 整月：进入某月一次性加载该月全部记录到内存（个人量级毫秒级），渲染该月内所有按天分组数据；滚动穿越月末加载下一个月。
  - **10 条是启动兜底而非分页块**：初始加载从当月开始逐月加载，直至累计条数 ≥ 10 或触达最早月份，取先达者（防空屏）。
  - 纯按天分组（UTC+8，标签「今天 / 昨天 / M 月 D 日」），无月份分隔头、无月份导航；滚动跨月自然连续（列表底部哨兵元素 + IntersectionObserver 触发加载上月）；按天分组为纯函数。
- 页面结构：无标题栏——首行左侧类型搜索输入（匹配已加载记录类型）、右侧同步按钮；下方虚拟列表；底部 tab（记录/设置）；右下角悬浮添加按钮（FAB）。
- 记录卡片：首行左侧彩色类型 Tag（类型→颜色固定映射，允许重复）、右侧时间（仅 HH:mm）；名称沿用原描述的主文字样式，描述在其下使用次级文字颜色。两者均保留换行并完整展示，不截断、不折叠；空字段省略。随后是自定义属性（灰色 Tag 横向排列自动换行）和图片缩略图行。具体类型的专属展示布局暂不实现。
- 编辑入口：FAB 新建；长按记录卡片打开编辑 bottom sheet，单击不执行操作（键盘 Enter/Space 仍可访问）。新建前可选择类型模板或自由表单；命中模板时锁定类型和预置属性结构，只允许修改值。表单包含时间 DatePicker、类型、名称（单行输入）、描述（自适应高度文本域）、图片区和自定义属性编辑器；名称与描述均可留空，独立保存，不互相替代。图片以正方形横向列表显示，右上角小型 IconButton 删除，末尾保留上传入口；布尔属性在 Switch 两侧显示「否」和「是」。新建内容关闭即丢弃，不存在草稿概念；编辑态删除记录需要二次确认。

## 9. UI 壳与设置页

- 普通文本输入、下拉选择和按钮沿用 Chakra 默认 `md`（40px 高），不重复声明 `size`；描述文本域最小高度同为 40px，多行时自动增高。设置列表行、悬浮添加按钮、图片角标及输入框内嵌按钮按各自布局保留尺寸。
- 两页底部 tab：记录页 / 设置页（tanstack-router 嵌套路由，tab 在父布局）。
- 页面文件位于 `app/routes/`；记录页和设置页由根布局保持 mounted，路由切换只改变可见性，避免列表和应用级状态重新加载。
- dark mode：Chakra ColorMode（`.dark` class），偏好存 localStorage，设置页 Switch 切换。
- 设置页：云端凭证入口（编辑 + 保存时真实连接验证，错误提示）、清理未引用图片（确认 → 扫描 → 删除 → 结果提示）；「记录」组包含类型模板与清空数据，当前不提供导出备份。
- 清空数据：弹窗显示「将清除所有本地及云端数据」、端点和桶名，输入框提示「输入桶名以确认」，匹配后可点击「确认」。清空 `records/`、`images/`、`type-templates.json`、`manifest.json`，再删图片缓存并单事务清空全部 IndexedDB 业务表，最后刷新。保留凭证、外观设置与无关云端文件；同步/图片清理时禁用，失败可重试。例如电脑和手机各清空一次，全部完成后再开始记录。
- 状态：跨页面或后台共享的数据使用应用级 Jotai Atom 或 app-level external store；表单草稿、筛选输入和弹窗开关保留在页面或组件内。`StorageAdapter`、当前 R2 适配器和 `ImageManager` 由 `app/runtime.ts` 组装并按应用生命周期复用；同步引擎保持纯函数模块，不是 React 组件或页面状态。
- `record-workflow` 统一编排记录保存/删除、UTC+8 月份 dirty 标记（跨月改时间标两个月）以及操作后的本地孤儿图片清理；UI 不直接碰 dirty。
- `cloud/sync/engine` 只负责云端版本比较和上传/下载。记录页触发全局同步，并在成功下载本地数据后清理孤儿图片、刷新记录与类型模板；同步引擎不依赖记录页工作流。
