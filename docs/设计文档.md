# 产品与运行架构

## 适用范围

- 只交付个人使用的 Android 应用，React 界面嵌入 Capacitor。
- 手机保存完整业务数据；没有云端配置或断网时仍可查看、编辑和添加图片。
- 云端是用户主动维护的备份，不承担在线查询，也不轮询状态。
- 领域词汇见 [CONTEXT.md](../CONTEXT.md)，对象格式见 [云端格式](cloud-storage-format.md)。

## 模块职责

| Module | 职责与 Interface |
| --- | --- |
| `src/app/` | 初始化原生数据和偏好，组装路由、同步上下文与跨 feature 生命周期 |
| `features/storage/` | 共享建表定义、SQLite 查询与事务、快照完整性检查 |
| `features/records/` | 记录编辑、分页展示，以及文件与数据库的保存流程 |
| `features/records/images/` | 草稿引用、文件保存、缩略图和显示地址 |
| `features/type-templates/` | 模板约束、属性规则和模板页面 |
| `features/cloud/credential/` | 连接表单、凭证草稿和验证 |
| `features/cloud/r2/` | SigV4 签名、对象元信息和文件传输 |
| `features/cloud/sync/` | 备份方向、条件提交、图片对齐和中断恢复 |
| `features/preferences/` | 本设备偏好；不进入业务备份 |
| `android/.../LocalDataPlugin.java` | SQLite、文件流、原生 HTTP、同步写入锁与亮屏 |
| `android/.../ImageDraftProvider.java` | 系统相册引用、内存管道预览和原生图片编码 |
| `tools/` | Android 打包、产物验证与本地发布审核 |

业务模块默认平铺，稳定的编辑、列表、图片、凭证、R2 和同步能力就近组织；类型单独放在 `type.ts` 或 `.type.ts`，不建立 barrel。见 [ADR-0007](adr/0007-feature-module-boundaries.md)。

## 本地记录与模板

- SQLite 是本机记录、模板和图片引用的事实来源；保存成功不依赖网络。
- 记录按 `(time, id)` 倒序游标分页，类型筛选进入全库 SQL 查询，日分组使用固定 UTC+8。
- 领域中的时间使用 `Date`，SQLite 保存绝对毫秒；编辑器未改时间时保留原毫秒。
- 模板按创建时间升序展示，时间相同时按类型代码点排序，各设备不使用语言排序规则。新增写真实时间，编辑不改变首次创建时间。
- 模板命中时锁定类型和预置属性结构；自由属性可增删。模板更改影响下次录入规则，不改写已保存记录的属性值。
- 文本与数值空值不保存，`false` 和 `0` 保留。选项属性允许列表外的字符串，输入新值不改变模板。

例如“阅读”模板增加“作者”后，打开已有记录时该字段为空；已有的自由备注仍保留。模板属性删除后，记录中的对应值作为自由属性继续存在。

## 图片与记录保存

1. 系统选图器返回相册 URI，草稿只保留进程内引用；WebView 与原生之间只传标识和文件元信息。
2. 缩略图最大 320px，大图草稿预览最大 2048px，由原生内存管道提供，不生成草稿图片文件。
3. 保存时逐张读取源图片，最长边 2048px、WebP 质量 80；不能识别为位图的图片按原字节流保存。
4. 写入临时文件、计算 SHA-256、同步到磁盘后原子提交，再在一个 SQLite 事务内保存记录、图片元信息和有序引用。
5. 文件或数据库失败时回收本次新文件，保留草稿引用供重试；取消编辑或移除草稿只释放引用。迟到结果不能进入下一次编辑。
6. 事务成功后检查受影响图片的剩余引用，最后引用移除才删除本体。异常遗留文件由下次同步对齐。

单张源图片上限 64 MiB，保存结果上限 16 MiB；草稿不积累整批图片二进制，预览工作线程数为 2。已保存本体始终保留本地副本，缩略图和必要的格式转换预览位于可再生缓存中，不上传。

例如选中 4000×3000 照片时，取消不会留下应用图片文件；保存会生成最大 2048×1536 WebP 本体。两条记录共享该图片时，删除第一条不会删除本体。

## 手动同步

### 方向与会话

- 打开应用、回到前台和网络变化均不检查云端。点击同步后先读取快照版本和图片清单，再比较本地修改序号。
- 云端有新备份时走恢复；本地也有未备份修改则先确认整库覆盖。取消确认保留本地数据且不弹结果 Toast。
- 已确认同一云端版本且有本地修改时走备份。云端版本回退、已确认快照消失或同版本内容不同会报错，不自动覆盖。
- 执行前取得原生会话并再次核对本地修改序号；会话期间拒绝业务写入，界面用全屏遮罩阻止继续编辑。

### 备份

1. 检查本地本体；可从当前备份修复缺失文件，无可用副本则失败。
2. 仅上传云端缺失或大小不符的图片，并发最多 2 个。
3. 导出完整 SQLite 快照，记录待确认提交信息，再用 ETag 条件提交。
4. 确认提交成功后保存本设备基线，再删除多余云端图片、对齐本地图片目录并核对集合。
5. 提交回包丢失时保留待确认信息，下次按版本和摘要核对，不盲目重传快照。

### 恢复

1. 以目标快照摘要作为工作目录标识，复用已完整下载的数据库和图片。
2. 校验数据库、引用与云端图片清单，估算缺失图片和必要磁盘余量。
3. 下载缺失图片，逐文件验证大小和 SHA-256；未完成文件不成为可复用本体。
4. 再次检查云端 ETag，图片齐全后原子安装数据库，持久化回执并对齐图片集合。
5. 准备失败或应用退出时继续使用原数据库；下次手动同步复用完成文件。数据库已安装但基线尚未写入时，通过回执补齐。

例如恢复 200 张图到第 80 张时进程退出，重开仍可查看当前记录；下次同步只补缺失文件。文件级恢复不等同于单文件字节断点续传。

### 时限与显示

- 普通网络请求总时限 15 秒；单文件总时限 3 分钟，连接与读写空闲保护同为 15 秒。
- 超时直接结束；其他可重试短暂故障最多尝试 2 次。快照提交结果不明时留待下次核对。
- 原生会话连续 45 秒无活动后自动解除写入锁和亮屏；迟到任务不能修改当前数据或解除新会话。
- 前台同步保持亮屏；结束、失败或超时后解除。不承诺锁屏或后台持续传输，也不提供人工停止入口。
- 同步弹窗高 152 CSS px，上下内边距各 20px；loading 下方始终一行状态，例如“上传图片（1/20）”，没有进度条或尾注。
- 每个出现的阶段至少展示 800 毫秒，同阶段计数立即更新，最后阶段满足时间后关窗；无文件的传输阶段不展示。
- 结果文案为“云端已更新”“本地已更新”“已是最新”；失败提示保留具体原因，长 Toast 可横向滚动。

## 容量与设备状态

图片以文件流传输，不把 GB 级数据放入 JS、SQLite 或整库内存。查询按页、图片按可见范围加载；下载前预估缺失文件和 16 MiB 余量。共同图片可复用，完全不同的两份图片库在安全替换期间可能接近双份占用。

凭证和配置草稿写入原生偏好，验证成功才建立连接；右上角关闭会使在途验证失效。APK 不包含个人凭证，不部署签名服务。覆盖安装依赖固定应用标识与签名；备份和签名私钥不进入仓库。
