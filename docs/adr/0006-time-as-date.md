# 时间表示：Date 对象替代 UTC+8 ISO 字符串

日期：2026-08-14
状态：已采纳
关联：修订 ADR-0003（其「以 ISO 字符串存储」的表示部分被本决策取代；UTC+8 归属政策保留不变）

## 决策

`LifeRecord.time` 及全部记录时刻改为 JS `Date` 对象（绝对瞬间），IndexedDB 的 `time` 键存 Date 类型键。月份归属仍按 UTC+8（ADR-0003 政策不变）。

## 背景

原 ADR-0003 以「UTC+8 ISO 字符串」为唯一时间表示，月份归属退化为字符串前缀。该表示只覆盖「按 UTC+8 墙钟月份」一种查询轴：

- 相对时间查询（最近 7 天 / 30 天、本周）需先构造与存储格式逐字一致的 UTC+8 边界字符串（偏移后缀、无毫秒），每新增一种查询形状就新增一处字符串手术；
- `time: string` 是裸字符串，任何垃圾值可编译通过（Primitive Obsession）；
- 完整性/正确性受限：字符串表示只在固定格式下成立，属「部分场景可行」，不满足奥卡姆剃刀「足以解决问题」的要求。

## 后果

- `monthOf` 从字符串前缀改为常数偏移换算：`new Date(t.getTime() + 8h)` 后取 UTC 字段。+8h 是常量（ADR-0003 政策），不是设备时区。
- 月份范围查询边界改为 Date 键范围：`monthStartUtc8(month)` 给出「当月 1 日 00:00+08:00」与「下月 1 日 00:00+08:00」对应的瞬间。
- 云端 JSON 序列化：`Date` 经 `JSON.stringify` 输出 UTC ISO（Z 后缀）。下载侧解析 JSON 后必须把 time 字符串转回 Date 再入本地——该转换是 CloudAdapter 实现的职责。
- IndexedDB 键类型由 string 变 Date：IDB 键按类型比较（数字 < 日期 < 字符串），混合类型会破坏范围语义。当前数据库版本为 2；从 v1 升级到 v2 只新增类型模板对象存储，不改写已有记录和图片。
- 排序：Date 键 `'prev'` 遍历 = 新在前；并列按主键 id 降序（既有契约不变）。
- 相对时间查询（未来）：下界直接 `new Date(Date.now() - 7 * 864e5)`，无需任何格式化。
- 时间边界使用 `date-fns`、`date-fns-tz` 和 `@date-fns/utc`；`src/utils/time.ts` 只是共享库调用的薄封装，不重新实现时区算法。月份进位用 `UTCDate`，避免设备本地时区影响范围计算。
