# 图片：S3 为唯一事实来源，仅随手动上传

图片只从相册选择，无拍摄概念；选图时通常本地压缩转 WebP，极少数浏览器无法解码或编码时保留原始 Blob。S3 是图片的唯一事实来源，已上传图片不进入 IndexedDB 业务数据；浏览器可使用 Cache Storage 按稳定对象路径缓存已成功读取的图片，缓存由浏览器按存储压力淘汰，缓存不可用时仍回退到签名 URL。未上传图片暂存于 IndexedDB 图片对象存储（id → Blob，并记录 createdAt 供本地孤儿兜底清理），上传成功后删除。

应用级唯一的非 React `ImageManager` 合并并发读取；列表和编辑表单同时显示同一图片时共享一个展示资源。React 调用方使用 `useImageSources`，不直接管理资源租约和 Object URL。ImageManager 内部组合来源解析与资源缓存；仍在显示的位置持有资源，离开显示位置的 Blob 展示资源进入有上限的 LRU 内存缓存（默认 32 MiB），超过上限时只淘汰最久未使用且当前无人显示的资源。记录页不主动销毁 manager，用空间换取再次进入记录时的加载速度；应用生命周期结束时由浏览器回收。无法取得 Blob 的短期签名直链不进入空闲内存缓存；Cache Storage 仍负责跨刷新复用。图片压缩、暂存和孤儿清理保持在 `features/records/images/` 下的独立 module。

关键取舍：**图片不自动上传**。手动上传时只上传「被本地记录引用且云端尚无」的图片——选图后放弃记录不会在云端产生孤儿，是预防而非清理。代价是图片在手动上传前仅存在于本地（与记录一致）。

云端图片删除不自动执行（删除记录、移除图片、异常遗留都不触发云端删除），仅提供手动「图片清理」功能（设置页入口文案为「清理未引用图片」）：扫描本地全部记录与云端全部图片，删除未被引用的云端图片。孤儿留存于云端是接受的代价，换取删除路径无任何隐式副作用。
