# 开发验证

## 本地回归

```bash
pnpm exec vitest run --exclude tests/r2.smoke.test.ts
pnpm build
```

- 本地回归不访问真实 R2；构建包含 TypeScript 检查。
- 连接与同步：验证无凭证、后台暂停与重连、过期结果隔离、请求总时限和冲突取消保留本地数据。
- 图片：验证暂存清理、内存资源共享、重建管理器后的缓存复用、缺图重试、缓存写入失败和清空范围。
- PWA：检查生产 worker 的清单覆盖全部页面资源，且每项具有 SHA-256 下载校验；生命周期与缓存路由由下方真实浏览器回归验证。

## 真实浏览器回归

首次运行需要安装测试浏览器，之后直接执行回归。脚本会自行构建到临时目录，无需先运行开发服务器。

```bash
pnpm exec playwright install chromium
pnpm test:pwa
```

也可使用已安装的 Google Chrome：

```bash
PWA_BROWSER_CHANNEL=chrome pnpm test:pwa
```

脚本使用独立浏览器上下文访问本机临时服务器，不读取现有浏览器配置或访问 R2。输出包含操作系统和 Chromium 版本。[浏览器用例](../tests/pwa-browser.mjs)覆盖：

- **接管与离线导航**：模拟 [Cloudflare HTML 规范化](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/)的 `/index.html → /` 307，以及 `/` 的同源重定向；检查缓存移除重定向历史，接管后连续刷新 3 次保留 HTML 类型与 CSP 响应头。断网后首次打开设置、模板页，再刷新深层路径及首页。
- **旧 worker 迁移**：先复现旧版导航失败，再从 `/sw.js` 更新；完整性失败拒绝安装，重试成功后保留未保存输入并等待旧页面关闭，激活后删除旧格式应用壳缓存。
- **Workbox 版本更新**：使用两次真实生产构建；安装失败保留旧条目，成功后新旧版本共存；waiting 期间刷新取得旧版，激活后取得新版并清理旧条目。
- **升级数据保留**：两类升级均比较完整本地存储快照，包括未同步记录、模板、同步状态、待上传图片、配置草稿、偏好和已上传图片缓存。
- **缓存故障与回退**：注入 Cache Storage 访问异常，确认在线导航可用；删除测试应用壳后验证挂起请求中止、恢复后可重试、在线 HTML 不回填旧预缓存。仅加速超时用例的时钟，同时核对请求时限为 10 秒。

缓存与升级规则见[设计文档：离线应用壳](设计文档.md#离线应用壳)。

### Cloudflare 静态资源环境

构建后可用本地 Wrangler 按 `wrangler.jsonc` 启动实际 Workers Static Assets 路由，另开终端执行预览回归：

```bash
WRANGLER_SEND_METRICS=false pnpm dlx wrangler dev --local --ip 127.0.0.1 --port 8788 --types=false
```

```bash
PWA_BROWSER_CHANNEL=chrome PWA_PREVIEW_ORIGIN=http://127.0.0.1:8788 pnpm test:pwa
```

`PWA_PREVIEW_ORIGIN` 也可指向已部署的 Cloudflare 预览地址。额外用例确认 `/index.html` 返回 307、`/` 返回 200，再验证接管后连续刷新及离线深层导航；不配置云端或写业务记录。未指定地址时跳过此用例。手机真机仍按下方清单检查。

## 浏览器与手机 PWA

离线检查使用生产构建；开发服务器不注册 Service Worker。

```bash
pnpm preview --host 127.0.0.1
```

桌面浏览器可用 localhost 检查；手机需访问已部署的 HTTPS 地址。在独立浏览器配置或测试桶中验证以下行为，生产数据不用于冲突或删除测试。

| 场景 | 操作与预期 |
|---|---|
| 无凭证启动 | 直接进入记录页；点击“已离线”才打开云端配置，空表单可取消；打开面板不聚焦输入框 |
| 接管后刷新 | 首次安装并确认 worker 已接管后，连续刷新至少 3 次，再直接打开并刷新 `/records`、`/settings`、`/settings/type-templates`；每次均进入应用 |
| 完整离线安装 | 在线打开并等待 Service Worker 安装完成；此前不访问模板页。断网重开后仍可首次进入设置、模板页 |
| 本地记录与模板 | 离线创建模板、带图片的记录，关闭整个浏览器或 PWA，再打开后仍可查看与编辑；只保存本地数据 |
| 已上传图片 | 在线同步后关闭整个浏览器，再断网重开。缓存存在的图片可显示，未缓存图片只显示可重试占位 |
| 验证中取消 | 用受控请求延迟连接结果，取消后再让旧请求成功；不保存凭证、不重新打开面板 |
| 连接与同步分离 | 首次连接、恢复网络只检查状态并保留本地数据；另行点击同步才上传或下载 |
| 网络故障与恢复 | 后台失败无 toast 或弹窗；手动失败提示具体原因。本地保存不等待挂起的云端请求，恢复后可再次重连 |
| 同步中途失败 | 真正同步时禁止并发编辑；已经下载的数据及时展示，未上传内容保留，失败后可重试 |
| 冲突取消 | 手机离线修改某月，另一设备上传同月更新。手机同步时取消覆盖，本地记录、模板及待上传图片均保留 |
| 新版安装失败 | 用受控响应让资源缺失或内容校验失败；旧版仍可离线启动，图片缓存保留 |
| 坏版本升级 | 旧 worker 已导致刷新失败时发布修复，等待更新安装，关闭所有本站点标签页及 PWA 窗口后重开；反复刷新正常，本地记录、模板和图片保持完整 |
| 新版安装成功 | 旧页面保留未保存输入；新版等待旧页面退出后激活，随后可离线启动，图片缓存保留 |

安装图标不代表资源已缓存完成。手机真机还需验证系统关闭、后台恢复和存储淘汰；桌面检查不能代替这些结果。缓存被浏览器淘汰或用户清除后需要重新联网，已上传图片不保证永久离线可用。

### 发布后的恢复

- 修复发布到同一 `/sw.js` 地址后，联网等待安装，关闭所有本站点标签页和 PWA 窗口再重开。
- 若旧 worker 仍阻断导航，必要时只在 Service Worker 调试面板注销本站点 worker，再联网刷新；须先发布修复，否则会重新安装故障版本。
- 在出问题的手机和干净的桌面 Chromium 中复核接管、刷新和离线启动，记录系统、浏览器版本及 worker 的 active/waiting 状态。自动化通过不代表手机生产环境已恢复。

恢复时保留 IndexedDB、LocalStorage 和 `omlr-images-v1` 图片缓存，避免丢失未同步数据。需要清理应用壳时只处理 `omlr-app-shell-*`，不使用“清除全部站点数据”或强制从云端覆盖本机数据。

## 真实 R2 冒烟

仅显式运行，使用专用隔离桶。将以下字段写入被 Git 忽略的 `.env.smoke`，或通过同名进程环境变量注入（环境变量优先）：

```dotenv
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_BUCKET=omlr-smoke
R2_ACCESS_KEY_ID=<test-access-key-id>
R2_ACCESS_KEY_SECRET=<test-access-key-secret>
```

```bash
pnpm exec vitest run tests/r2.smoke.test.ts --mode smoke
```

- 缺少完整凭证时跳过；桶名必须以 `-smoke` 结尾。
- 桶不存在时尝试创建；无创建权限时需预先建好。
- 测试写入伪月份 `2999-12` 和随机图片，结束后清理并恢复原 manifest；不要并发运行或与其他操作共用该桶。

产品规则见[设计文档](设计文档.md)，云端格式见[存储格式](cloud-storage-format.md)。
