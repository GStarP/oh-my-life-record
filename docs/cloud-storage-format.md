# S3/R2 存储格式

## 对象布局

```text
data/
├── database.sqlite
└── images/
    └── {imageId}.{extension}
```

应用仅访问同桶 `data/`；桶中只保留当前数据库和图片对象，不存放说明文档。

## 数据库快照

`data/database.sqlite` 可独立打开。表、索引和字段以共享 [schema.sql](../src/features/storage/schema.sql) 为准：

- `records`：记录及其绝对毫秒时间；属性保存为字符串、数值或布尔值组成的对象。
- `type_templates`：类型、图标、属性定义与 `created_at`；排序按创建时间升序，时间相同按类型代码点排序。
- `images`：不可变图片 ID、相对路径、实际媒体类型、字节数和 SHA-256。
- `record_images`：记录与图片的有序引用。
- `meta`：本地修改序号。

数据库标识为 `application_id=1330465874`、`user_version=1`。打开数据库时准备模板创建时间字段；尚无时间的模板按已确认顺序补录，编辑保留创建时间。

快照对象头示例：

```text
Content-Type: application/vnd.sqlite3
x-amz-meta-schema-version: 1
x-amz-meta-revision: 4
x-amz-meta-sha256: <完整快照的64位小写十六进制SHA-256>
```

`Content-Length`、`ETag`、上述元信息必须完整。ETag 是条件提交凭据，不解释为文件摘要。首次提交使用 `If-None-Match: *`，后续提交使用已读取 ETag 的 `If-Match`；条件失败不覆盖其他备份。

## 图片对象

- 扩展名与实际媒体类型一致，本体保持独立文件；数据库不存图片二进制或下载 URL。
- 图片 ID 对应不可变内容。同一路径内容摘要不同会中止同步。
- 上传设置真实 `Content-Type`；数据库保存大小与 SHA-256，下载完成核对摘要后才成为可复用文件。
- 日常同步按路径和大小复用已确认对象，只传缺失图片，避免反复读取 GB 级图片做全量摘要。
- 缩略图、显示预览、偏好设置、WAL、同步基线及传输工作文件不上传。

例如记录引用图片 `A`，数据库保存 `images/A.webp` 及其大小和摘要；快照与该图片共同构成可恢复的备份。图片上传成功后本地本体仍保留。

## 一致性范围

成功同步后，记录、模板、图片引用、图片集合及本体字节一致。运行中的数据库管理 WAL 和内部页状态，不以本地活跃文件与快照逐字节相同作为业务一致性条件。

提交、恢复和删除顺序见 [设计文档](设计文档.md#手动同步)。凭证和同步状态属于设备状态，不出现在数据库快照中。
